## Support levels and limits

- **Implemented and live-tested:** active/fallback questions, documented answers, human escalation, worker reuse, bounded handoffs/plans/contracts, independent rejection/correction/re-audit, integration acceptance, obsolete-source applicability, concurrent project scopes, restart reuse and final collision/cancellation recovery.
- **Implemented with component failure tests:** reused transport request IDs; preparation and post-dispatch commit faults; late-history/cancellation interleavings; stale context/contract refusal; uncertain write-claim retention. Not every injected failure was reproduced against the remote service.
- **Partial support:** question detection requires the dedicated dynamic tool or exact final marker. Unmarked prose needs inspection. Old workers use new-turn answers. Expertise uses explicit records; hashes cover listed sources. Architecture guards cover declared paths/contracts and require real integration tests.
- **Unsupported/unqualified:** automatic security approvals, autonomous creative choices, remote exactly-once execution, a hidden background scheduler, hostile-tenant confidentiality, universal Codex compatibility and live Linux/macOS/remote-host operation. Experimental APIs can change.

The coordinator loop must remain operating. Escalation records a matter for that coordinator to present; it sends no independent notification. Bridge loss requires reconciliation; unknown outcomes never authorize resend. See [security boundaries](SECURITY.md) and [workflow details](ADVANCED_SKILLS.md). Simple fixtures qualify orchestration, not arbitrary product correctness.
