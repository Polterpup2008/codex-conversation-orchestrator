# Autonomous coordination qualification — 0.5.6

Validation date: 26 October 2026. Windows, official Codex CLI `0.164.0-alpha.11.1`, Python 3.12.10, existing ChatGPT sign-in. This record complements the retained 0.4 qualification; it does not relabel earlier runs as final-version executions.

## Verified behavior

- **118 disk-backed automated tests pass, with no skips.** The prior 87 regression tests remain included. New cases cover native human provenance across complete human message blocks, direct designation grammar, reported/quoted/third-party text, subsequent qualifications/corrections and withdrawals, forks, caller identity, grant/revocation interleavings, runtime policies, real NTFS junction rejection through the full runtime/venv pipeline, artifact-read recovery, installer opt-in preservation and retained legacy resources.
- Two actual concurrent coordinators on **0.5.0** activated from their direct human appointment without a separate operator grant. One created **three developers, one modeler and one shared independent auditor**. The four independently owned deliveries passed four separate artifact-bound audits and acceptance decisions using that same auditor; combined content validation passed. An ordinary active worker question was answered by its coordinator, and a worker promotion to Coordinator was refused. The other coordinator correctly created no workers for an activation-only objective.
- That full-team run encountered real Windows artifact-read denial. Its coordinator delegated content-preserving read-access maintenance to the original writers, rechecked the files and completed the audits without a human confirmation. `ARTIFACT_READ_DENIED` now explains this supported recovery before reserving an audit send. Maintenance does not fabricate a delivery or bypass audit freshness.
- A genuine **0.5.1** final-run failure exposed missing caller UUID in the MCP process and private-registry write denial in a workspace-write shell. It was retained as failure evidence. **0.5.2** resumed the same chat and original nomination successfully with a read-only native shell challenge, preserving its ID/history and authorization on repeated activation. No shell registry write, sandbox escape or repeated nomination was needed.
- The **installed 0.5.4, 0.5.5 and final 0.5.6** runtime helpers were exercised against isolated real per-user Python fixtures whose sandbox access was deliberately absent: observed denial, ACL backup, DACL-only RX addition, and successful version probes under both developer and auditor policies. Runtime/external write handles stayed denied; developer writes inside its workspace remained allowed and auditor writes denied. The original Python and parent ACL stayed unchanged. The temporary runtimes were removed.
- Fresh **0.5.6** activation and repeated activation passed on one unchanged connection, with native shell caller proof and both role policies ready. No temporary MCP approval override was passed to the final CLI runs; they used the profile's explicit own-plugin opt-in.
- Actual upgrade testing exposed an old open process whose package resources had been removed by official CLI cache replacement. Its original missing files were restored from its exact original install source, without replacing live files. The final installer retains/restores missing prior-version resources, including after a simulated CLI failure; existing files remain untouched. The already-open legacy host's status continued working after the final install. A host reload is still required to refresh old tool inventories.
- The installed profile has explicitly opted into routine approval for **this plugin's MCP server only**. Other configuration, project authority, leases, sandbox policy and native command/file approvals remain enforced. A native shell challenge prints only the connection nonce and current chat UUID; it writes no files or registry state.

## Independent source review

The original independent release reviewer retained earlier findings and reproduced failures before correction. The first autonomy candidate was rejected for provenance/role confusion, concurrent authorization overwrite/revocation, runtime after revocation, reparse-path escape and missing caller identity. A second candidate was rejected for adjacent designation cases and lexical paths being lost earlier in the runtime pipeline. Later checks found that partial quotes and separate human text blocks/messages could omit qualifications or withdrawals. Those failures were preserved, with regression reproductions added; green original tests were not treated as evidence that the defects did not exist.

The final source recheck and package/publication gates are recorded in the release completion update below.

## Evidence boundaries

Version-only Python probes use `-I -B -S`. They do not qualify third-party dependencies, CUDA, training, arbitrary executables or all runtime-library contents. Hash coverage lists the selected executable/config/base entry points and DLLs; it is not a recursive dependency integrity scan. Read/execute repair is limited to an ordinary per-user Windows Python installation, with original lexical paths checked before resolving away any junction.

Native caller/history verification is an accidental-role guard for a trusted OS account, not cryptographic authentication against an actor able to rewrite sessions or the registry. Other platforms have unit coverage; these live results do not establish their full runtime compatibility. Existing project source, workers and product acceptance are not qualified merely by upgrading the plugin. Old host tool inventories can require refresh; installation cannot add missing tool types to an immutable running host inventory.

Caller verification corroborates a native execution-tool transcript naming the installed helper and current nonce, with its matching output. It is not an independently attested execution environment; arbitrary same-user shell code remains trusted.

Runtime policies follow the [official Windows sandbox documentation](https://learn.chatgpt.com/docs/windows/windows-sandbox). The explicit per-server tool approval opt-in uses the [documented MCP configuration](https://learn.chatgpt.com/docs/extend/mcp); it does not answer native approval requests. Private transcripts, paths, IDs, ACL backups and databases remain excluded from distribution.
